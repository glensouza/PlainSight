The `package-name` parameter value `'signage-server'` does not match the actual package name in GitHub Container Registry. The Docker image is published as `ghcr.io/glensouza/plainsight/signage-server`, so the package name reference may be incorrect.

## Suggested Solution

Update the `package-name` in the workflow file (line 64) to match the actual package name format. Try one of these options:

**Option 1:** Use the full path
```yaml
package-name: 'plainsight/signage-server'
```

**Option 2:** Verify the exact package name in GitHub Packages UI and use that exact value.

**Option 3:** If this is the first run and no package exists yet, the cleanup step will fail. Consider adding a condition to skip cleanup if the package doesn't exist, or allow this step to fail gracefully:

```yaml
- name: Clean up old images (keep 5 most recent)
  if: github.event_name != 'pull_request'
  continue-on-error: true
  uses: actions/delete-package-versions@v5
  with:
    package-name: 'signage-server'
    package-type: 'container'
```
